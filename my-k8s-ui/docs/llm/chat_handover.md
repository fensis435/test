# チャット上限に備えた引き継ぎ戦略

チャットの文脈は新しいチャットに引き継がれないので、**「引き継ぎ用のドキュメントをLLMに作らせておく」**のが最善策です。

---

## 事前にやっておくこと

上限が近づいたと感じたら（あるいは定期的に）、以下のプロンプトを打ちます。

---

### 💬 引き継ぎドキュメントを生成させる

> **あなた：**
> このチャットでの会話の内容を、新しいチャットでゼロから続きを始められるように「引き継ぎ書」としてまとめてください。以下を含めてください。
>
> 1. **プロジェクト概要**（技術スタック・構成・エントリーポイント）
> 2. **把握済みのデータモデル・主要ロジック**
> 3. **発見済みの問題点リスト**（重要度付き）
> 4. **実施済みの修正内容**（どのファイルの何を変えたか）
> 5. **現在進行中のタスク・次にやること**
> 6. **新しいチャットへの引き継ぎ指示文**（そのままコピペできる形で）

## 新しいチャットでの再開手順

```
1. ソースコードを再アップロード（ZIPごと）
      ↓
2. 引き継ぎ書のコピペ用テキストを貼り付け
      ↓
3. 「前回の続きで〇〇から始めます」と一言添える
```

これだけで、新しいチャットでも文脈を失わずに続けられます。

---

## より安全な運用：定期スナップショット

長期プロジェクトなら、**節目ごとに引き継ぎ書を更新してファイル保存**しておくと安心です。

```
会話の節目（機能ひとつ把握・修正ひとつ完了）ごとに
  → 「引き継ぎ書を最新化して」と依頼
  → テキストをローカルに保存
```

引き継ぎ書自体をClaudeに作らせてしまうのがポイントで、自分で書く手間なく常に最新の文脈を保持できます。
