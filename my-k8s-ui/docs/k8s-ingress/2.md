NGINX Gateway Fabric(NGF)は構成要素が ingress-nginx より少し増えます。**Gateway API本体のCRD**、**NGF自体のCRD**、**Helmチャート**、**コンテナイメージ**の4点セットを air-gapped 環境に持ち込む必要があります。

## 全体構成の把握

```
Gateway API CRDs (kubernetes-sigs/gateway-api)  ← Kubernetes標準のGateway/HTTPRoute等のCRD定義
        ↓ 前提として必須
NGF独自のCRD (nginx/nginx-gateway-fabric)         ← NGF固有拡張(SnippetsFilter等)
        ↓
NGF Helmチャート (oci://ghcr.io/nginx/charts/nginx-gateway-fabric)
        ↓
コンテナイメージ (control plane + data plane の2種)
```

## 手順1: インターネット接続がある構築用機での準備

### ① Gateway API標準CRD

```bash
# Kubernetes公式のGateway API CRD(NGFのバージョンと互換性のあるものを選ぶ)
curl -LO https://github.com/kubernetes-sigs/gateway-api/releases/download/v1.5.1/standard-install.yaml
```

NGFのバージョンごとに対応するGateway APIバージョンが決まっているので、導入予定のNGFバージョンのREADME/Technical Specificationsで対応表を確認してください(バージョンのミスマッチはリソースが認識されない原因になります)。

### ② NGF独自CRD

```bash
curl -LO https://raw.githubusercontent.com/nginx/nginx-gateway-fabric/v2.6.3/deploy/crds.yaml
```

### ③ Helmチャート(OCIレジストリからpull)

```bash
helm pull oci://ghcr.io/nginx/charts/nginx-gateway-fabric \
  --version 2.6.3 \
  --destination ./charts
```

### ④ イメージ参照の洗い出し

```bash
helm show values oci://ghcr.io/nginx/charts/nginx-gateway-fabric --version 2.6.3 \
  | grep -A3 -E "^(nginxGateway|nginx):" 
```

構成は大きく2イメージです。

- コントロールプレーン: `ghcr.io/nginx/nginx-gateway-fabric:<version>`
- データプレーン(NGINX OSS本体): `ghcr.io/nginx/nginx-gateway-fabric/nginx:<version>`

これらをskopeoで既存フローに乗せてprivate ECRへ。

```bash
skopeo copy \
  docker://ghcr.io/nginx/nginx-gateway-fabric:2.6.3 \
  docker://<account-id>.dkr.ecr.<region>.amazonaws.com/nginx-gateway-fabric/ngf:2.6.3

skopeo copy \
  docker://ghcr.io/nginx/nginx-gateway-fabric/nginx:2.6.3 \
  docker://<account-id>.dkr.ecr.<region>.amazonaws.com/nginx-gateway-fabric/nginx:2.6.3
```

### ⑤ Helmチャート自体もECRへpush

```bash
aws ecr create-repository --repository-name nginx-gateway-fabric/chart
helm push ./charts/nginx-gateway-fabric-2.6.3.tgz \
  oci://<account-id>.dkr.ecr.<region>.amazonaws.com/nginx-gateway-fabric
```

## 手順2: air-gapped環境への転送

これまでのcharts-syncer/S3/踏み台経由フローに、上記①②のYAMLマニフェスト2つと③のtgzを乗せるだけです。イメージは④で既にECRに直接pushされているので追加の転送作業は不要です。

## 手順3: 適用順序(重要)

**CRDは各リソースの定義サイズが大きく、`kubectl apply` の単体では `metadata.annotations: Too long` エラーになりやすいので `--server-side` を使ってください。**

```bash
# ① Gateway API CRD
kubectl apply --server-side -f standard-install.yaml

# ② NGF CRD
kubectl apply --server-side -f crds.yaml

# ③ NGF本体をHelmでインストール(イメージ参照をECRに向ける)
helm install ngf oci://<account-id>.dkr.ecr.<region>.amazonaws.com/nginx-gateway-fabric \
  --version 2.6.3 \
  --create-namespace -n nginx-gateway \
  --set nginxGateway.image.repository=<account-id>.dkr.ecr.<region>.amazonaws.com/nginx-gateway-fabric/ngf \
  --set nginxGateway.image.tag=2.6.3 \
  --set nginx.image.repository=<account-id>.dkr.ecr.<region>.amazonaws.com/nginx-gateway-fabric/nginx \
  --set nginx.image.tag=2.6.3
```

これらの `--set` はArgoCD Application の `values-prod.yaml` にそのまま落とし込める形です。既存のvalues-dev/prod.yamlパターンに乗せる場合は、この4項目(control plane repository/tag、data plane repository/tag)を書いておけば足ります。

## 注意点: NGFはHelmインストール時点ではデータプレーン(LoadBalancer)を作らない

ingress-nginxと違い、NGFの `helm install` はコントロールプレーン(ClusterIP)だけを作ります。実際にNLB経由で公開するトラフィック用のnginxインスタンス(データプレーン)は、`Gateway` リソースを別途apply して初めて作成されます。

```yaml
apiVersion: gateway.networking.k8s.io/v1
kind: Gateway
metadata:
  name: tenant-gateway
  namespace: nginx-gateway
spec:
  gatewayClassName: nginx
  listeners:
    - name: https
      port: 443
      protocol: HTTPS
      hostname: "*.example.local"
      tls:
        mode: Terminate
        certificateRefs:
          - name: example-local-wildcard-tls
```

このGatewayが作られたタイミングで、AWS Load Balancer Controller annotationを使って以前設計したのと同じ内部NLB(scheme: internal、target-type: ip)が自動生成されるよう `nginx.service` 側にアノテーションを設定します。ここは前回のingress-nginx Service定義とほぼ同じ考え方です。

---

ここまでで疎通確認用の土台(CRD+コントロールプレーン+NLB)が揃います。次はワイルドカードHostname + テナント識別ヘッダーによる `HTTPRoute` の定義に進めますか?on-premのnginx-ingressアノテーション(`nginx.ingress.kubernetes.io/*`)からの読み替えが必要になる箇所です。
