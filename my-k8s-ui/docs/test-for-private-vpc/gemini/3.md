NGINX Ingress側でHTTPS（TLS）を終端する場合、「ALB経由でNGINXもTLSにする方式（End-to-End TLS）」**と、**「NLBを使って暗号化のまま暗号文を通過させ、NGINXで直接終端する方式（TLSパススルー）」の2つの選択肢があります。

---

### パターン1：ALB ＋ NGINX で暗号化（End-to-End TLS）

ALBで一度復号したトラフィックを、ALBからNGINX Podへ向ける際にもう一度HTTPSで暗号化して送信する構成です。

```
[Client] ───( HTTPS / ACM )───► [ ALB ] ───( HTTPS / 内部証明書 )───► [ NGINX Pod ]
                              ▲ 1次終端                             ▲ 2次終端

```

#### 1. TLS証明書（Secret）の作成

NGINXで終端するため、Kubernetes内にTLS証明書をSecretとして用意します。

```yaml
# tls-secret.yaml
apiVersion: v1
kind: Secret
metadata:
  name: nginx-tls-secret
  namespace: ingress-nginx
type: kubernetes.io/tls
data:
  tls.crt: <BASE64_ENCODED_CERT>
  tls.key: <BASE64_ENCODED_KEY>

```

#### 2. ALB Ingress マニフェスト

ALBからNGINXへの転送プロトコルを **`HTTPS`** に変更します。

```yaml
# alb-ingress.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: alb-ingress
  namespace: ingress-nginx
  annotations:
    ingress.class: alb
    alb.ingress.kubernetes.io/scheme: internet-facing
    alb.ingress.kubernetes.io/target-type: ip
    alb.ingress.kubernetes.io/listen-ports: '[{"HTTPS": 443}]'
    alb.ingress.kubernetes.io/certificate-arn: arn:aws:acm:ap-northeast-1:123456789012:certificate/xxx
    # ★ バックエンドへの転送プロトコルを HTTPS に指定 ★
    alb.ingress.kubernetes.io/backend-protocol: HTTPS
spec:
  rules:
    - http:
        paths:
          - path: /*
            pathType: ImplementationSpecific
            backend:
              service:
                name: ingress-nginx-controller
                port:
                  name: https # NGINX の HTTPS ポート (443) へ転送

```

#### 3. NGINX 側の Ingress マニフェスト

NGINX Ingress Controller で先ほどの Secret を使って終端させます。

```yaml
# nginx-ingress.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-ingress
  namespace: default
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - example.com
      secretName: nginx-tls-secret # 1で作成したSecret名
  rules:
    - host: example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: app-service
                port:
                  number: 80

```

### パターン2：NLB ＋ NGINX で直接終端（TLSパススルー）

ALB（L7）ではなく **NLB（L4 Network Load Balancer）** を使い、証明書管理や暗号化の終端処理を完全にNGINX Ingress（Kubernetes内）へ一元化する構成です。

```
[Client] ───( HTTPS / TLS )───► [ NLB ] ───( TCP パススルー )───► [ NGINX Pod ]
                                                                 ▲ TLS終端

```

#### NLB 用の Service マニフェスト

AWS Load Balancer Controller を使って Network Load Balancer（`type: LoadBalancer`）を作成し、暗号化通信のままNGINX Podへバイパスします。

```yaml
# nlb-nginx-service.yaml
apiVersion: v1
kind: Service
metadata:
  name: ingress-nginx-controller
  namespace: ingress-nginx
  annotations:
    # AWS Load Balancer Controller で NLB をプロビジョニング
    service.beta.kubernetes.io/aws-load-balancer-type: external
    service.beta.kubernetes.io/aws-load-balancer-nlb-target-type: ip
    service.beta.kubernetes.io/aws-load-balancer-scheme: internet-facing
spec:
  type: LoadBalancer
  selector:
    app.kubernetes.io/name: ingress-nginx
  ports:
    - name: http
      port: 80
      targetPort: 8080
    - name: https
      port: 443
      targetPort: 8443 # ポート443の通信をそのまま復号せずNGINXへ渡す

```

---

### パターンの使い分けまとめ

* **ACMで証明書を自動更新・管理したい場合**
➔ 前回の **「ALBのみで終端」** または パターン1の **「End-to-End TLS」**
* **クライアント認証（mTLS）や特殊なTLS設定をNGINX側で細かく制御したい場合**
➔ パターン2の **「NLB ＋ NGINX終端」**
