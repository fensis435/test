完全Private（インターネット接続なし）環境では、パブリックのACM証明書（無料のパブリック認証局）は**DNS検証や証明書発行ができないため使用できません**。

SSMのポート転送でテストしている開発環境であれば、要求されるセキュリティ要件に応じて**3つのアプローチ**があります。

---

### アプローチ1：ALBを「HTTP（ポート80）」で運用する（★開発・検証に最も推奨）

インターネット接続がなく、SSMポート転送経由でローカルPCからアクセスするだけであれば、**TLS化（HTTPS）を免除してALBをHTTP（80番ポート）で動かす**のが最もシンプルでトラブルが起きません。

* **証明書**: 不要
* **Ingress設定**: `listen-ports` を `HTTP:80` のみにし、`certificate-arn` アノテーションを削除します。
* **メリット**: 構成がシンプルで、証明書エラーやリダイレクトループのトラブルが発生しません。

---

### アプローチ2：AWS Private CA（プライベートACM）を使用する（ALBでHTTPS必須の場合）

「本番構成に合わせてどうしてもALBでHTTPS（443）を終端したい」という場合は、AWS内部のプライベート認証局サービス**AWS Private CA**を作成し、そこから発行した証明書をACM経由でALBにアタッチします。

* **仕組み**: 外部インターネットとの通信なしで、VPC内で完結する証明書を発行・アタッチできます。
* **注意点**: AWS Private CAは**月額約$400の固定費**が発生するため、開発・検証環境で導入する場合はコストにご注意ください。

---

### アプローチ3：NGINX Ingress側に「自己署名証明書」を置く

ALBではなく、NGINX Ingress Pod内に `cert-manager` や `openssl` で作成した自己署名証明書（オレオレ証明書）を配置して終端する構成です。

* **構成例**:
* ALB（またはNLB）は通信をそのままNGINXへ転送する。
* NGINX Ingressの `Secret` に自己署名証明書（`tls.crt` / `tls.key`）を格納して終端する。


* **メリット**: AWS Private CAを使わずに無料でHTTPS（TLS）の検証が可能です。

---

### SSMポート転送を使ったテストの実行手順例

完全Private環境で Internal ALB へアクセスする場合、踏み台EC2（またはSSM Agentが動いている環境）を中継役にして、**リモートホスト宛てのSSMポート転送**を行います。

#### 1. SSMポート転送コマンドの実行（ローカルPCのターミナル）

```bash
aws ssm start-session \
  --target <踏み台EC2のインスタンスID> \
  --document-name AWS-StartPortForwardingSessionToRemoteHost \
  --parameters '{"host":["<Internal-ALBのDNS名またはIP>"],"portNumber":["80"]}' \
  --local-portNumber 8080

```

#### 2. ローカルPCからのアクセス確認

* **HTTP（アプローチ1）の場合**:
ブラウザやcURLで `http://localhost:8080` にアクセスします。
* **HTTPS（アプローチ2・3）の場合**:
`https://localhost:8080` （自己署名証明書の場合は `curl -k` などで証明書検証をスキップ）でアクセスします。
