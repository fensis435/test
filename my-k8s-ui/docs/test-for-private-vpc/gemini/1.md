Cの構成（**ALB → Target Group → NGINX Pod IP**）において、ALBがNGINX IngressのPodを特定・指定する仕組みは、**「AWS Load Balancer Controller」**がKubernetesの**`Service`（または`EndpointSlice`）を経由してPodのIPアドレスを自動的に検出・登録する**という流れで行われます。

具体的な設定方法と仕組みは以下の通りです。

---

### 1. 実際の仕組み（自動連携フロー）

手動でPodのIPアドレスをTarget Groupに設定するわけではありません。以下のコンポーネントが連携して自動的に登録・更新されます。

```
[Ingress (ALB定義)]
    │ (target-type: ip)
    ▼
[AWS Load Balancer Controller] ──(Kubernetes APIを監視)──► [Service (ClusterIP)]
    │                                                            │
    │ AWS API呼び出し (RegisterTargets)                           ▼
    ▼                                                  [Endpoints / Pod IP]
[ALB Target Group] ─────────── Direct Traffic ────────────► [NGINX Pod]

```

1. **NGINX Podの準備**: NGINX Ingress ControllerのPodが起動すると、Kubernetesの `Service`（通常は `ClusterIP`）によって各PodのIPアドレスが `Endpoints` リソースに紐付けられます。
2. **Ingressの定義**: ALBを作成するための `Ingress` リソースを作成し、アノテーションに `alb.ingress.kubernetes.io/target-type: ip` を指定します。バックエンドとしてNGINXの `Service` を指定します。
3. **Controllerによる登録**: **AWS Load Balancer Controller** がIngressの設定を検知し、指定された `Service` の裏にいる **PodのIPアドレスを自動で取得** します。
4. **Target Groupへの登録**: ControllerがAWS APIを呼び出し、取得したPodのIPアドレスをTarget Groupのターゲット（`target-type: ip`）として直接登録します。

---

### 2. 具体的なマニフェスト（YAML）設定例

#### (1) NGINX用の Service (type: ClusterIP)

まず、NGINX Ingress Pod群をまとめる通常のServiceを作成します。

```yaml
apiVersion: v1
kind: Service
metadata:
  name: nginx-ingress-controller
  namespace: ingress-nginx
spec:
  type: ClusterIP # NodePortやLoadBalancerである必要はありません
  selector:
    app.kubernetes.io/name: ingress-nginx # NGINX Podのラベルを指定
  ports:
    - name: http
      port: 80
      targetPort: 8080
    - name: https
      port: 443
      targetPort: 8443

```

#### (2) ALB用の Ingress リソース

次に、ALBをプロビジョニングするためのIngressリソースを作成します。ここで **`target-type: ip`** を指定するのが最大のポイントです。

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: alb-to-nginx-ingress
  namespace: ingress-nginx
  annotations:
    # AWS Load Balancer Controller に ALB 作成を指示
    ingress.class: alb
    # Internal ALB の作成
    alb.ingress.kubernetes.io/scheme: internal
    # ★ ここで Target Group の種類を IP 指定に設定 ★
    alb.ingress.kubernetes.io/target-type: ip
spec:
  rules:
    - http:
        paths:
          - path: /*
            pathType: ImplementationSpecific
            backend:
              service:
                name: nginx-ingress-controller # (1)で定義したService名
                port:
                  name: http

```

---

### 3. Cの構成（IP Target）が成立するための前置条件

この仕組みが動くためには、以下の前提条件が必要です。

* **AWS VPC CNI を利用していること**
PodのIPアドレスがVPC内のサブネットから直接割り当てられている必要があります（EKSのデフォルトのネットワークプラグインであれば問題ありません）。
* **AWS Load Balancer Controller がクラスタ内にインストールされていること**
KubernetesのAPIを監視し、Target GroupのIPアドレスを動的に登録・削除する役割を果たします。Podがスケールアウト/インした際も、自動でTarget Groupのターゲットが追従・更新されます。
