実務で CloudFormation のテンプレートをゼロから（白紙から）書き始める人はほとんどいません。

多くのエンジニアは「信頼できるベース（型）」をどこからか持ってきて、自分の環境に合わせて微調整（パラメータ変更やタグ付け）をしています。公式サイトのドキュメントが重くて使いにくいのも、エンジニア共通の悩みです。

「公式サイト以外」で、状況に応じたテンプレートを探すのに役立つサイトやリポジトリを紹介します。

---

## 1. GitHub の公式サンプル集（最強のベース）
AWSが公式に管理しているリポジトリです。ここは比較的シンプルで、そのままコピペして使いやすいコードが揃っています。

* **[aws-cloudformation-templates](https://github.com/aws-cloudformation/aws-cloudformation-templates)**
    * **特徴**: VPC、S3、EC2、RDSなど、サービスごとの「基本形」が置いてあります。
    * **使い方**: `aws/services/` フォルダの中を覗くと、各リソースの YAML が見つかります。

## 2. AWS Partner Solutions (旧 Quick Start)
もっと実践的で「本番環境レベル」の構成が見たい場合に最適です。
* **[AWS Partner Solutions Templates](https://aws-quickstart.github.io/templates-examples.html)**
    * **特徴**: 「高可用なVPC」「踏み台ホスト」「Active Directory」など、複数のリソースを組み合わせた**「完成形」**が公開されています。
    * **使い方**: アーキテクチャ図と一緒に公開されているので、設計の勉強にもなります。

## 3. asecure.cloud (セキュリティ重視の逆引き)
「セキュリティ的に正しい設定」済みのテンプレートを探せる便利なサイトです。
* **[asecure.cloud](https://asecure.cloud/)**
    * **特徴**: 「S3を公開しない設定」「暗号化したRDS」など、特定の要件に基づいたスニペット（断片）を検索・生成できます。公式サイトよりずっと軽いです。

## 4. Former2 (既存リソースから生成)
「やりたいことはあるけど、コードが書けない」という時の裏技です。
* **[Former2](https://former2.com/)**
    * **特徴**: AWSコンソールでポチポチ手動で作ったリソースをスキャンして、**それを再現するための CloudFormation テンプレートを自動生成**してくれます。
    * **使い方**: 「手動で作る → コード化する → 整理する」という流れが作れるため、学習に最適です。

---

## 💡 賢い「テンプレート」の使い分け

自分で考えるべきなのは「どのリソースを作るか」ではなく、以下の **3点だけ** です。

1.  **命名規則 (`Tags` や `Name`)**: 自社のルールに合わせる。
2.  **キャパシティ (`InstanceType` など)**: 予算と負荷に合わせる。
3.  **ネットワーク設計 (`CidrBlock`)**: 他の環境と被らないようにする。

> **結論**: 
> テンプレートは **「探して、拾って、直す」** ものです。
