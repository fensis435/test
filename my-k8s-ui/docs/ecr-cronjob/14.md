選ぶパターンによって、Pod Identity（IAMロール・ポリシー）が「不要なケース」**と**「設定が必要なケース」に分かれます。

---

### パターン別の IAM 設定の違い

| パターン | Pod への Pod Identity 設定 | 理由 |
| --- | --- | --- |
| **パターン1:** `helm install --version "*"` | **不要** | Helm 自体が OCI レジストリ経由でタグ一覧を取得するため。ESO の Secret だけで完結します。 |
| **パターン2:** `aws ecr describe-images` | **必要** | Pod 内で AWS CLI / SDK を実行して ECR API を叩くため、AWS 権限が必須になります。 |
| **パターン3:** CI/CD から引数で渡す | **不要** | バージョン文字列を外から受け取るだけなので、Pod 自体は AWS API を叩きません。 |

---

### パターン 2 を選ぶ場合の IAM ポリシー設定

もし Pod 内で `aws ecr describe-images` などのコマンドを実行して最新タグを取得する場合は、Pod Identity 経由でその Pod に ECR 読み取り権限を付与する必要があります。

**追加が必要な IAM ポリシー例:**

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "ecr:DescribeImages",
        "ecr:ListImages"
      ],
      "Resource": "arn:aws:ecr:ap-northeast-1:<ACCOUNT_ID>:repository/my-chart"
    }
  ]
}

```

このポリシーを割り当てた IAM ロールを作成し、対象の Pod（ServiceAccount）に **Pod Identity Association** を設定します。

---

### おすすめの判断基準

* **Pod の権限を最小限（AWS 権限なし）に保ちたい場合:**
* **パターン 1** (`--version "*"`) または **パターン 3** を選択します。Pod 側の Pod Identity 設定は**完全に不要**となり、ESO の Secret マウントだけで動作するため、最もシンプルかつ安全です。


* **Pod 内のスクリプトで柔軟に ECR のメタデータを解析・処理したい場合:**
* **パターン 2** を選択し、上記の `ecr:DescribeImages` ポリシーを持たせた Pod Identity を設定します。
