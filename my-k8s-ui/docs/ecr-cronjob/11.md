完全プライベート（AirGap）環境の EKS クラスタに ESO を導入するには、**「必要リソース（イメージ・Helmチャート）のプライベートレジストリ（ECR等）への転送」** と **「AWS サービス用 VPC エンドポイントの作成」** が必須となります。

---

### 前提条件：必要な VPC エンドポイント

インターネット通信が一切できないため、以下の AWS Interface/Gateway エンドポイントが VPC 内に作成されている必要があります。

* **`com.amazonaws.<region>.sts`** (EKS Pod Identity の一時資格情報取得に**必須**)
* **`com.amazonaws.<region>.ecr.api`** & **`com.amazonaws.<region>.ecr.dkr`** (ECR からのイメージ pull に必須)
* **`com.amazonaws.<region>.s3`** (ECR のイメージレイヤーダウンロード用 Gateway エンドポイント)
* **`com.amazonaws.<region>.secretsmanager`** (Secrets Manager 連携用)

---

### インストール手順

1. **インターネット接続環境で成果物を準備:**
端末（開発PCなど）で ESO の Helm チャートとコンテナイメージをダウンロードします。

```bash
# 1. Helm チャートのアーカイブを取得
helm repo add external-secrets https://charts.external-secrets.io
helm pull external-secrets/external-secrets --tar

# 2. 必要なコンテナイメージを pull（バージョンは適宜変更）
ESO_VERSION="v0.9.18" # 例
docker pull ghcr.io/external-secrets/external-secrets:${ESO_VERSION}
docker pull ghcr.io/external-secrets/external-secrets:${ESO_VERSION}-cert-controller
docker pull ghcr.io/external-secrets/external-secrets:${ESO_VERSION}-webhook

# 3. イメージを tar ファイルに保存して転送準備
docker save ghcr.io/external-secrets/external-secrets:${ESO_VERSION} > eso.tar
docker save ghcr.io/external-secrets/external-secrets:${ESO_VERSION}-cert-controller > eso-cert.tar
docker save ghcr.io/external-secrets/external-secrets:${ESO_VERSION}-webhook > eso-webhook.tar

```


2. **プライベート VPC 内の ECR にイメージを push:**
成果物をプライベート環境へ持ち込み、プライベート ECR リポジトリへ push します。

```bash
# ECR リポジトリを作成（未作成の場合）
aws ecr create-repository --repository-name external-secrets/external-secrets
aws ecr create-repository --repository-name external-secrets/external-secrets-cert-controller
aws ecr create-repository --repository-name external-secrets/external-secrets-webhook

# タグ付けと Push（プライベートECR宛て）
REGISTRY="<YOUR_ACCOUNT_ID>.dkr.ecr.<region>.amazonaws.com"

docker tag ghcr.io/external-secrets/external-secrets:${ESO_VERSION} ${REGISTRY}/external-secrets/external-secrets:${ESO_VERSION}
docker push ${REGISTRY}/external-secrets/external-secrets:${ESO_VERSION}

# （cert-controller, webhook も同様に tag & push）

```


3. **custom-values.yaml の作成:**
ECR のイメージを参照するように指定した `custom-values.yaml` を用意します。

```yaml
# custom-values.yaml
installCRDs: true

image:
  repository: <YOUR_ACCOUNT_ID>.dkr.ecr.<region>.amazonaws.com/external-secrets/external-secrets
  tag: "v0.9.18"

certController:
  image:
    repository: <YOUR_ACCOUNT_ID>.dkr.ecr.<region>.amazonaws.com/external-secrets/external-secrets-cert-controller
    tag: "v0.9.18"

webhook:
  image:
    repository: <YOUR_ACCOUNT_ID>.dkr.ecr.<region>.amazonaws.com/external-secrets/external-secrets-webhook
    tag: "v0.9.18"

```


4. **AirGap 環境で Helm インストール実行:**
持ち込んだ Helm チャートの tar ファイルと `custom-values.yaml` を指定してインストールします。

```bash
helm install external-secrets ./external-secrets-0.9.18.tgz \
  --namespace external-secrets \
  --create-namespace \
  -f custom-values.yaml

```


5. **Pod Identity 設定と動作確認:**
事前に作成しておいた Pod Identity Association により、通信が VPC エンドポイント経由で STS に届くことを確認します。

```bash
# 1. Pod Identity の割り当て確認（AWS CLI）
aws eks create-pod-identity-association \
  --cluster-name <YOUR_CLUSTER_NAME> \
  --namespace external-secrets \
  --service-account external-secrets \
  --role-arn arn:aws:iam::<YOUR_ACCOUNT_ID>:role/<YOUR_ESO_ROLE>

# 2. ESO Pod のステータス確認
kubectl get pods -n external-secrets

```
