AWS 側のインフラ設定（IAM ロールや EKS Pod Identity Association）を **CloudFormation (CFN)** で記述すると、手動での AWS CLI コマンド実行が不要になり、テンプレート一つで再現・自動化できるようになります。

---

### CFN 化するリソースの範囲

1. **`AWS::IAM::Role`**: ESO 自身が使用する IAM ロールとポリシー
2. **`AWS::EKS::PodIdentityAssociation`**: EKS クラスタ、Namespace、ServiceAccount と IAM ロールを紐付けるリソース

※ Kubernetes 内のリソース（ESO の Helm インストールや `ExternalSecret` マニフェスト）は、通常通り Helm や kubectl、GitOps ツール等で管理し、**AWS 側の基盤設定を CFN で管理する**という役割分担になります。

---

### CloudFormation テンプレート例 (YAML)

以下の CFN テンプレートを実行するだけで、ESO 向けに必要な AWS 側の権限設定が完結します。

```yaml
AWSTemplateFormatVersion: '2010-09-09'
Description: External Secrets Operator (ESO) Pod Identity Resources

Parameters:
  EKSClusterName:
    Type: String
    Description: Target EKS Cluster Name

Resources:
  # 1. ESO 用の IAM ロール
  ESOPodIdentityRole:
    Type: AWS::IAM::Role
    Properties:
      RoleName: !Sub "${EKSClusterName}-eso-role"
      AssumeRolePolicyDocument:
        Version: '2012-10-17'
        Statement:
          - Effect: Allow
            Principal:
              Service: pods.eks.amazonaws.com
            Action:
              - sts:AssumeRole
              - sts:TagSession
      Policies:
        - PolicyName: ESO-ECR-And-SecretsManager-Policy
          PolicyDocument:
            Version: '2012-10-17'
            Statement:
              # ECR トークン取得権限
              - Effect: Allow
                Action:
                  - ecr:GetAuthorizationToken
                Resource: "*"
              # Secrets Manager 参照権限（必要に応じて）
              - Effect: Allow
                Action:
                  - secretsmanager:GetSecretValue
                  - secretsmanager:DescribeSecret
                Resource: "*"

  # 2. Pod Identity Association (EKS と IAM ロールの紐付け)
  ESOPodIdentityAssociation:
    Type: AWS::EKS::PodIdentityAssociation
    Properties:
      ClusterName: !Ref EKSClusterName
      Namespace: external-secrets
      ServiceAccount: external-secrets
      RoleArn: !GetAtt ESOPodIdentityRole.Arn

Outputs:
  ESORoleArn:
    Value: !GetAtt ESOPodIdentityRole.Arn
    Description: IAM Role ARN created for ESO

```

---

### CFN 化することによる変化・メリット

* **手順の簡略化:**
以前コマンドで実行していた `aws eks create-pod-identity-association` や IAM ロール作成の長い CLI スクリプトが、スタックを作成/更新（`aws cloudformation deploy`）するだけで完了します。
* **ライフサイクル管理:**
不要になった場合に CloudFormation スタックを削除すれば、関連する IAM ロールや Pod Identity の紐付けが一括で綺麗に削除されます。
* **依存関係の制御:**
EKS クラスタ自体を CFN で作成している場合、クラスタの作成完了を待って自動的に Pod Identity を関連付けるといった依存関係（`DependsOn`）を組むことができます。
