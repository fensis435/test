### 1. CronJobの詳細マニフェスト

Kubernetes内でSecretを作成・更新するためには、**Pod用のServiceAccount** と **K8s RBAC（権限）**、そして **CronJob** のセットが必要です。

以下は、Argo CDが直接読み込める形式のSecretを自動更新する完全なマニフェスト例です。

```yaml
apiVersion: v1
kind: ServiceAccount
metadata:
  name: ecr-token-renewer-sa
  namespace: argocd
---
# Kubernetes内でSecretを更新・作成するための権限
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: ecr-token-renewer-role
  namespace: argocd
rules:
- apiGroups: [""]
  resources: ["secrets"]
  verbs: ["get", "list", "create", "update", "patch"]
---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: ecr-token-renewer-rb
  namespace: argocd
subjects:
- kind: ServiceAccount
  name: ecr-token-renewer-sa
  namespace: argocd
roleRef:
  kind: Role
  name: ecr-token-renewer-role
  apiGroup: rbac.authorization.k8s.io
---
apiVersion: batch/v1
kind: CronJob
metadata:
  name: ecr-token-renewer
  namespace: argocd
spec:
  schedule: "0 */6 * * *" # ECRトークンの有効期限は12時間のため、6時間ごとに更新
  successfulJobsHistoryLimit: 1
  failedJobsHistoryLimit: 2
  jobTemplate:
    spec:
      template:
        spec:
          serviceAccountName: ecr-token-renewer-sa
          restartPolicy: OnFailure
          containers:
          - name: renewer
            image: amazon/aws-cli:latest
            command:
            - /bin/sh
            - -c
            - |
              set -e
              # kubectl のインストール（標準イメージに含まれないため）
              curl -sLO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"
              chmod +x kubectl

              REGION="ap-northeast-1"
              ACCOUNT_ID="$(aws sts get-caller-identity --query Account --output text)"
              TOKEN=$(aws ecr get-login-password --region ${REGION})

              # Argo CD用のHelm Repository Secretを作成・更新
              cat <<EOF | ./kubectl apply -f -
              apiVersion: v1
              kind: Secret
              metadata:
                name: ecr-helm-repo-secret
                namespace: argocd
                labels:
                  argocd.argoproj.io/secret-type: repository
              type: Opaque
              stringData:
                type: helm
                name: ecr-helm-repo
                url: ${ACCOUNT_ID}.dkr.ecr.${REGION}.amazonaws.com
                enableOCI: "true"
                username: AWS
                password: ${TOKEN}
              EOF

```

### 2. 起動直後（Apply直後）は必ず実行されるか？

**いいえ、デフォルトでは起動直後（`kubectl apply` 直後）には実行されません。**

KubernetesのCronJobは、`schedule`（例：`0 */6 * * *`）で指定された**最初のスケジュール時刻が来るまで待機**します。そのため、デプロイ直後はSecretが存在せず、Argo CDなどが失敗してしまいます。

#### 対策（初回実行させる方法）

以下のいずれかの方法で対応します。

1. **ワンショットの `Job` も一緒に apply する（推奨）**
マニフェスト群の中にCronJobと同じ処理を行う一度限りの `Job` を含めておきます。デプロイ直後に即座にJobが走り、Secretが生成されます。
2. **CI/CDパイプラインからCronJobを手動キックする**
`kubectl apply` を実行した直後に、以下のコマンドを実行します。
```bash
kubectl create job --from=cronjob/ecr-token-renewer ecr-token-renewer-init -n argocd

```

### 3. EKS Pod Identity 用の CloudFormation テンプレート

EKS Pod Identityを使用する場合、**「Pod Identity用の信頼関係（Trust Policy）」** を持ったIAMロールと、**「ECRトークン取得用のIAMポリシー」** が必要です。

また、`AWS::EKS::PodIdentityAssociation` を使って、K8sのServiceAccountとIAMロールを紐付けます。

#### CloudFormation テンプレート例

```yaml
AWSTemplateFormatVersion: '2010-09-09'
Description: IAM Role and Pod Identity Association for ECR Token Renewer

Parameters:
  ClusterName:
    Type: String
    Description: Name of the EKS Cluster
    Default: my-eks-cluster

Resources:
  # 1. IAM Role for ECR Token Renewer
  EcrTokenRenewerRole:
    Type: AWS::IAM::Role
    Properties:
      RoleName: !Sub ${AWS::StackName}-ecr-token-renewer-role
      # EKS Pod Identity 用の信頼関係（Trust Policy）
      AssumeRolePolicyDocument:
        Version: '2012-10-17'
        Statement:
          - Effect: Allow
            Principal:
              Service: pods.eks.amazonaws.com
            Action:
              - sts:AssumeRole
              - sts:TagSession
      # ECRトークン取得用のIAMポリシー
      Policies:
        - PolicyName: EcrGetTokenPolicy
          PolicyDocument:
            Version: '2012-10-17'
            Statement:
              - Effect: Allow
                Action:
                  - ecr:GetAuthorizationToken
                # ecr:GetAuthorizationToken はリソース制限不可のため '*' を指定
                Resource: '*'

  # 2. EKS Pod Identity Association (K8s SA と IAM Role の紐付け)
  EcrTokenRenewerPodIdentityAssociation:
    Type: AWS::EKS::PodIdentityAssociation
    Properties:
      ClusterName: !Ref ClusterName
      Namespace: argocd
      ServiceAccount: ecr-token-renewer-sa
      RoleArn: !GetAtt EcrTokenRenewerRole.Arn

Outputs:
  RoleArn:
    Value: !GetAtt EcrTokenRenewerRole.Arn
    Description: ARN of the IAM Role created for Pod Identity

```

#### ポイント

* **信頼関係（`AssumeRolePolicyDocument`）**:
Serviceとして IRSA（`ec2.amazonaws.com` や OpenID Connect）ではなく、**`pods.eks.amazonaws.com`** を指定し、Actionに `sts:AssumeRole` と **`sts:TagSession`** を含める必要があります。
* **権限（`ecr:GetAuthorizationToken`）**:
AWSの仕様上、トークン取得APIである `ecr:GetAuthorizationToken` はリソース絞り込みがサポートされていないため、`Resource: '*'` と設定します。
