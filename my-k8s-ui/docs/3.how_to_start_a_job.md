ActiveJob で定義したジョブ（InstallJob／StartJob／StopJob／RestartJob／UninstallJob）は、Rails のコントローラやコンソールから `perform_later`（非同期実行）または `perform_now`（同期実行）で起動します。以下に主な起動方法をまとめます。

---

## 1. コントローラ内で起動する

先ほどの `AppsController` の例でも使っているように、操作を受け付けるアクション内でジョブをキックします。

```ruby
class AppsController < ApplicationController
  before_action :set_app, only: [:start, :stop, :restart, :destroy]

  def create
    app = App.create!(name: params[:name], status: 'stopped')
    op  = Operation.create!(app: app, action: 'install', status: 'pending', progress: 0)

    # InstallJob を非同期にキック
    InstallJob.perform_later(op.id)

    render json: { operationId: op.id }, status: :created
  end

  def start
    op = Operation.create!(app: @app, action: 'start', status: 'pending', progress: 0)

    # StartJob を非同期にキック
    StartJob.perform_later(op.id)

    render json: { operationId: op.id }, status: :accepted
  end

  # stop, restart, destroy (uninstall) も同様に perform_later(op.id)
  # …
end
```

- `perform_later` はキューにジョブを積むだけで即座には実行されず、バックグラウンドワーカー（Sidekiq／Resque／DelayedJob など）が拾って処理します。  
- `perform_now` を使うと同じプロセス内で即時実行されます（テストやデバッグ時に便利）。

---

## 2. Rails コンソールから手動で起動する

デバッグや動作確認のために、Rails コンソールから直接キックできます。

```bash
$ rails c
> op = Operation.create!(app: App.first, action: 'start', status: 'pending', progress: 0)
> StartJob.perform_later(op.id)
```

あるいは即時実行版も:

```ruby
> RestartJob.perform_now(op.id)
```

---

## 3. ActiveJob のアダプター設定

`config/application.rb` か各環境設定（`config/environments/*.rb`）で、使用したいバックグラウンドジョブアダプターを指定しておきます。たとえば Sidekiq を使う場合:

```ruby
# config/application.rb
module YourApp
  class Application < Rails::Application
    # 省略…
    config.active_job.queue_adapter = :sidekiq
  end
end
```

- そのうえで `bundle exec sidekiq` コマンドを別ターミナルで起動しておく必要があります。  
- 開発中、ログにジョブ処理状況が出る `:inline` アダプターも利用できます。  

```ruby
# config/environments/development.rb
config.active_job.queue_adapter = :inline
```

---

## 4. Cron やスケジューラから定期的にジョブを起動する

サーバメトリクスの集計やメンテナンスタスクの場合、`whenever` や `sidekiq-scheduler` を使って定期実行できます。

例: `config/schedule.rb`（whenever）

```ruby
every 1.day, at: '2:00 am' do
  runner "CleanupOldAppsJob.perform_later"
end
```

---

### まとめ

- **コントローラ** 内では `YourJob.perform_later(operation_id)` を呼び出す  
- **Rails コンソール** からも `perform_later`／`perform_now` で起動可能  
- `config.active_job.queue_adapter` を設定し、バックグラウンドワーカーを起動する  
- 定期的なジョブは **Cron（whenever）** や **sidekiq-scheduler** でスケジュール  

これで、Helm／Kubernetes 操作を封じ込めたジョブを必要に応じて柔軟にキックできます。
