ALBでACM証明書を用いてHTTPSを終端し、ALBからNGINX PodへはHTTP通信（ポート80）で転送する構成（CのIP Target形式）のマニフェスト例です。

---

### 1. NGINX Ingress 側の設定（ConfigMap & Service）

ALBからHTTPで通信が届くため、**「元のアクセスがHTTPSだったこと」をNGINXが認識できるように設定する**必要があります。

```yaml
# nginx-configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: ingress-nginx-controller
  namespace: ingress-nginx
data:
  # ALBが付与する X-Forwarded-Proto: https ヘッダーを正しく解釈する設定
  use-forwarded-headers: "true"
---
# nginx-service.yaml
apiVersion: v1
kind: Service
metadata:
  name: ingress-nginx-controller
  namespace: ingress-nginx
spec:
  type: ClusterIP # IP Target(C)なので ClusterIP で問題ありません
  selector:
    app.kubernetes.io/name: ingress-nginx
  ports:
    - name: http
      port: 80
      targetPort: 8080 # NGINX Pod の HTTP 受け取りポート

```

---

### 2. ALB を生成する Ingress マニフェスト

AWS Load Balancer Controller に対して、ACM証明書をセットしたALBの構築を指示します。

```yaml
# alb-ingress.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: alb-ingress
  namespace: ingress-nginx
  annotations:
    # AWS Load Balancer Controller を指定
    ingress.class: alb
    # 外部公開用 (内部向けなら internal)
    alb.ingress.kubernetes.io/scheme: internet-facing
    # IP Target 構成 (Pod IP へ直接送信)
    alb.ingress.kubernetes.io/target-type: ip
    # 受信ポートの設定 (80 と 443 を開放)
    alb.ingress.kubernetes.io/listen-ports: '[{"HTTP": 80}, {"HTTPS": 443}]'
    # ★ ACM 証明書の ARN を指定 (ここで HTTPS 終端) ★
    alb.ingress.kubernetes.io/certificate-arn: arn:aws:acm:ap-northeast-1:123456789012:certificate/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
    # HTTP (80) へのアクセスを HTTPS (443) へ自動リダイレクト
    alb.ingress.kubernetes.io/ssl-redirect: '443'
    # ヘルスチェックの設定 (NGINX のヘルスチェックエンドポイントを指定)
    alb.ingress.kubernetes.io/healthcheck-path: /healthz
    alb.ingress.kubernetes.io/healthcheck-port: '8080'
spec:
  rules:
    - http:
        paths:
          - path: /*
            pathType: ImplementationSpecific
            backend:
              service:
                name: ingress-nginx-controller # (1)で定義した NGINX Service 名
                port:
                  name: http # HTTP (80) で転送

```

---

### 設定時の重要ポイント

1. **`use-forwarded-headers: "true"` の必要性**
* ALBでTLSを終端すると、ALB ➔ NGINX 間は純粋な **HTTP通信** になります。
* これにより、NGINXやその奥のアプリケーション（Web APIやフロントエンド）が「アクセスがHTTPで来た」と誤認し、不要なリダイレクトループ（`http://` へのリダイレクト発生など）を起こすことがあります。
* `use-forwarded-headers: "true"` を入れることで、ALBが付与した `X-Forwarded-Proto: https` をNGINXが信頼し、後続Podへ「元のリクエストはHTTPSだった」と正しく引き継ぎます。


2. **ヘルスチェックポートの整合性**
* NGINX Ingress Controller Podは、通常のトラフィック用ポート（8080等）とは別にヘルスチェック用パス（`/healthz`）を持っています。Target Groupのヘルスチェックが通らない場合は `healthcheck-port` の値を確認してください。
