まず進捗率を「本当に正確に％で出す」のは難しいです。Helm や Kubernetes の Go/Ruby クライアントはあくまで「操作のリクエストを投げる」「ステータスを取得する」だけで、その裏側でどれだけリソースが作られ、何秒で終わるかを教えてくれるわけではありません。

## まずは現実的な進捗算出パターン

1. Deployment のロールアウト状態で算出  
   - `desiredReplicas` に対して `updatedReplicas` や `availableReplicas` の比率を取る  
   - 例：`progress = updatedReplicas / desiredReplicas * 100`  
2. Job や CronJob の完了数で算出  
   - 指定されたタスク数のうち何個が完了したか  
3. Helm リリース操作の擬似ステップ数で算出  
   - テンプレート生成→K8s API 送信→各種リソース Ready の３段階に分けて 33%、66%、100% など  

## Rails 側での実装イメージ

1. **K8s クライアントでのポーリング**  
   ```ruby
   deployment = Kubeclient::Resource.new(...)
   status = client.get_deployment_status(name, namespace)
   desired = status.spec.replicas
   updated = status.status.updatedReplicas || 0
   progress = (updated.to_f / desired * 100).round
   ```
2. **Helm Ruby SDK 経由でのステップ把握**  
   - `helm install/upgrade` のログ出力をフックして「親リソース作成」「Hooks 実行」「完了確認」というフェーズを手動カウント  
3. **カスタムコントローラー or Operator**  
   - CRD のステータスフィールドに細かい進捗情報を持たせ、Rails からその CRD を監視して進捗を集計  

## 注意点とTIPS

- 全リソース一括で何秒かかるかは環境依存なので、**割合モデルでの擬似進捗表示**に留めるのが無難  
- もしもっと細かく知りたければ、**Pod の Ready/Event をリアルタイムで集計**し、Rails 側で WebSocket 経由で流す方法がある  
- Argo Rollouts や Flux などのツールを使うと、よりリッチなステータスを外部 API で取得できる  

---

### さらに踏み込むなら  

- Kubernetes の **Custom Metrics API** を使い、コントローラーがメトリクスをポストする  
- **Prometheus** と **Alertmanager** を使って各種リソース作成／更新完了をトリガーにイベントを発行  
- Helm 3 の Go SDK を踏み台にして、リリースごとのステップ数を明示的にプラグイン実装  

これらを組み合わせることで、Rails 側でも「進捗バーがユーザーにとって意味ある数字を示す」UX に近づけられます。
